# 设计与统一记录

读构建逻辑及所选类别后，先写可见因果：头部提供方向与身份，附着光／火焰提供能量，世界粒子记录经过的路径，连续尾带提供速度连贯，命中清头与余尾消散给出结束信号。并非每种 projectile 都要所有职责；箭头可只有主体和轻尾，喷口尾焰可完全没有内部头部。

将用户要求与实现假设分开。设计冻结主体形状、亮暗层次、头尾尺度关系、阶段节奏和空间归属；帧池、播放速度、真实 scale 和层组织可以待选图后调整。不可因没找到完整火球就悄悄交付圆形光点；可用火舌群构造主体时，写明组合方案和损失。

尾迹是主要视觉贡献时，按[构建逻辑](construction.md#尾迹职责与层数)判断是否需要内尾、外尾、碎尾等独立职责。将确有贡献的职责写入现有roles，分别说明宽窄、明暗、历史长度、连续性与结束节奏；无需新增固定字段或一律拆成三层。简洁箭尾可只保留一条线，流星可能需要亮内尾与柔外尾的对比。增加同类粒子数量不等于增加尾迹层次。

选图前冻结这些对比目标，暂不把职责与配置层、素材文件一一绑定。图像本身已提供内核和软晕时允许合层；需要独立寿命、空间或运动时再拆。预算不足先减没有独立贡献的重复光晕、可选烟或碎屑，保留主体尾迹的关键对比，总配置仍最多8层。

材料需求按独立运动单元列：头部轮廓、短火舌、单片冰屑、星形装饰、局部烟团、沿长度衰减的连续带、直束核心。说明需要静态变体还是时间动画、前向轴、透明／黑底加色语义、端点布局及不可分离的烘焙内容。文件名只辅助查找；一种职责不等于一种 texture，几种兼容静态帧可在一层随机。

合层看材料 Source、混合、空间、时间和运动是否一致。多套世界烟可合成变体层；头部 local 与余烟 world 即使同图也不能为了减层合并。被移除的第二圈光晕通常损失次要亮度，移除唯一头部轮廓则损失主体身份。优先保留后者，每份配置最多 8 层。

reuse 保留素材仍要重新判断方向、尺度与结束方式；partial 只重新检索需要替换的职责；reselect 才全量选材。这些是有对应用户编辑要求时的工作方式，不要求任何特定服务存在。materials.json 对实际候选做观察后，配置用 adaptations 或独立说明解释变化，不重写设计消除缺口。

停止策略也进入设计：哪些实际层是应立即消失的头部／附着光，哪些粒子要自然排空，哪些尾带要保留。绑定以最终 layerId 为准；角色被合并、删去后同步修改宿主说明，不生成指向不存在层的结束操作。

同一真实 texture 可以跨层、跨职责复用，各层参数独立。规划共用候选时描述各职责的形态、时序和运动需求；真实观察后分别判断适配，不能预先要求每个职责独占一张图，也不能因共用就视为全部满足。
