# 素材

## 事实与观察

输入design是冻结的design.json全文，内含requirements、acceptance、design、needs、retainedRoleIds、dynamicPrompt和host；当前need及候选另行提供。按其中的目标与可适配边界评价，不另行改写设计。

观察当前候选的原始图像及元数据，围绕所需职责说明形态、边缘、透明/黑底编码、可见宽度、方向性、染色限制和时间阶段。metadata、像素测量、视觉推断和未知分开写入当前 evidence/observations 文本；不虚构新的输出属性。

帧分为单张、兼容变体、有序动画、混合图集、未知。使用原始 ordinal，不发明 atlas frame 名。说明真正看过的帧、可用静态池与动画 clip；一张少量帧 contact sheet 不证明整张大图集都可用。动画 timing 未知时 fps 是设计值。每帧不同 duration 不属于本配置能力。分页观察须在evidence指出本页ordinal范围、首尾形态与中间变化方向，让汇总能衔接相邻页；单页未覆盖完整动作，不等于已经否定整图动画。起始空帧可能表示尚未显形，结束空帧可能表示消散，不能按静态随机池的选帧规则一律删除。

元数据的 unclassified、proposed 或 unknown 表示源标注未确认，不等于视觉上不可用。根据实际看过的帧判断：形态、色调、用途与尺寸相容的同阶段帧，可以组成明确 ordinal 的静态随机池，不需要证明时间顺序。若所看完整区间具有连续形态与合理阶段顺序，可在 evidence 中记录视觉确认的 clip；播放时长仍可作为设计值。没有足够视觉证据时才保留未知。不要因无法确认动画，就把一整张多帧图集退化为只允许一张静态图。

alpha bounds 对透明图有用；不透明黑底 add 图的 alpha bounds 会覆盖全画布，应参考 bright bounds 和原图。阈值不能替代最终曝光判断。检查帧中心/透明边距差异造成的跳动；scale 无法消除枢轴漂移。

发光素材分开描述明亮核心和柔弱外晕的可见范围。说明尺寸来自像素测量还是视觉估计；没有可靠亮核测量时保留不确定性，不能用几乎不可见的外晕宽度代替主体宽度。此信息用于配置尺度与曝光，不新增素材评分门槛。

## 图中单元与可执行运动

先在现有evidence中说明一帧画的是什么及可承担的职责：单个元素（一个水滴/碎片）、局部群簇（一团烟或一片喷雾），或完整现象（已有爆心、外缘和飞散的整次爆炸/水冠）。同时说明其中哪些运动已经烘焙、哪些需要粒子独立运动；不新增分类字段。

一张水滴场上的许多点会共享一颗粒子的轨迹，适合薄喷雾覆盖，不直接等于许多独立抛落水滴。完整爆炸帧可承担主体，但缩小并重复发射常变成多枚小爆炸，而非局部火团。按本次职责评价，不能因有水滴/火焰像素就评为高度匹配；群簇和完整图本身并非低质量材料。当前帧结构无法提供需要的单元时说明用途差异，不想象可裁出的帧。

评价候选能否参与实现角色，而不是要求单张图等于最终画面。结合need与design.adaptable，判断局部元素是否具有可保留的轮廓、方向与锚点，以及位置/角度/时序组合是否能形成目标：例如单条有分叉的闪电可参与多向放电，不能仅因它竖直或不围绕中心就否决；透过旋转后的实际纹理仍须具有电弧识别特征。evidence写清组合用途与不能补偿的部分，score评价适配代价；确实无法满足用户关键要求时仍为不满足。单图形态不是整体现象，不自动构成硬失败。

选材汇总保留这个判断，并综合所有页面给出可用ordinal池或连续clip。完整动作不同阶段的帧可按阶段独立使用，但不会因此变成局部元素；区分“帧序未知”与“各帧是不同形状”。如果完整已观察区间有稳定锚点、轮廓连续演化与合理先后，可明确给出clip和依据，不让元数据unknown覆盖已观察事实；不能跨未观察的分页边界假定连续。

## 选择与适配

优先实际可用性，再用偏好分数排名。通过硬条件但风格分低的资源可以说明差异后使用；高分也不能让无效资源变有效。当前视觉评分输出为 score、meetsConstraints、evidence；批量选择按当前 scores/retryQuery/retryReason 协议，检索轮次由服务端控制，不自行扩展。scores中每个key直接逐字复制对应candidate.key（包括revision后缀），每个候选恰好一次；不要从标题、相似ID或其他候选拼接。

score 统一使用 0–100 分制，例如较适合为 78 分，不写成 0.78。单页观察分数只评价所展示帧；最终候选分数综合全部观察与可用帧，不要求每一页都承担同一职责。

第一轮选择中，存在 meetsConstraints=true 且 score>=60 的候选时，retryQuery=null、retryReason=""。否则必须提供不同于首轮的 retryQuery 和具体 retryReason。需要第二轮时把失败原因转为不同的形态词或检索视图，例如把水滴场改为查找居中的单颗滴形，而非只扩写原句。若首轮只是在搜整幅现象却没有合适结果，目标可组合时改查有辨识特征的局部单元，不要在第二轮进一步收紧整图形状。不要凭名称过滤掉用途相符的灰度素材，也不要求未确认的kind标注。第二轮只返回scores，覆盖本次packet.candidates列出的全部候选（含首轮保留项与本轮新增项），不能只返回新增候选；沿用仍有效的首轮观察即可，不因重新列出而改变评分。fuzzy 可选择满足硬条件的低分替代，exact 仍要求至少 60 分。素材评分只用于选材，不作为最终配置的视觉质量硬校验。

组合核对尺度、色调、视角、前向轴、亮度和时序。一个资产可提供多个兼容 clip/变体；不同 TextureSource 不能直接放进同一个帧集。共享材料需职责相容，不能把烟图拉伸后称为冲击环。

materials.json 使用 designHash、textureSets、resources、observations、gaps。resources 的 selected/reused 含真实 candidate 与 evidence；unresolved 含 need、description、assumedSize。observations 每项由服务端补入needId、候选key、image与frameOrdinals，再附实际score、meetsConstraints、evidence；用身份字段关联素材和帧页，不凭数组位置或相似描述猜测，gaps 为 {need,description} 数组。绑定、URL 和 textureSets 来源由服务端生成。可用帧/clip及适配依据写入协议允许的证据文本；不凭名称猜动画。

差异可以是数值换算、层组织调整或不可补偿缺口。单张烟可以团块扩散，不能声称内部翻卷；tint 与贴图相乘，饱和橙色贴图不能任意变为纯蓝色。

素材名与设计职责可以不同：灰白烟纹理的形态、透明度和可染色性适合时，可以用暖色与add承担火焰。评估实际外形与阶段，不因名称不同就拒绝。原Prefab的材质和UV用法是原素材的证据；当前资产若是参照原图重新生成，不能据此自动确认当前帧序、亮度或锚点。

## 缺口报告

找不到材料则 resources 标记 unresolved；gaps.description 用文本说明职责、目标影响和纹理生成 brief。没有 placeholder textureSet，不输出 UNRESOLVED 纹理绑定。已有可用层继续进入配置；可运行结果允许交付，缺失视觉贡献作 warning。没有任何可用层才失败。

brief 明确视角、形态、用途、透明背景或适合 add 的黑底、帧布局/顺序、期望阶段和边缘。brief 只建议生成内容，不代表自动调用生成工具。

同一真实 texture 可跨层、跨职责复用，参数各自独立。共用候选须先真实观察，再按每项职责分别判断形态、帧语义、方向、亮度与可补偿范围；一种职责适配不代表其他职责自动适配。
